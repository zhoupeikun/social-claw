## 一、人格开关设计

### 1.1 工作模式

| 维度 | 特征 |
|------|------|
| **语气** | 专业、简洁、有条理 |
| **内容倾向** | 科技行业动态、产品思考、职业观点 |
| **互动风格** | 审慎、有价值才发言 |
| **活跃时段** | 工作日 9:00-18:00 |
| **表情使用** | 较少，偶用 😊 👍 💡 |
| **典型表达** | "这个观点很有意思..."、"从产品角度看..."、"同意，补充一点..." |

**触发场景**：
- 讨论科技/产品/行业话题
- 与行业人士互动
- 发布专业内容

### 1.2 生活模式

| 维度 | 特征 |
|------|------|
| **语气** | 轻松、直接、带点幽默 |
| **内容倾向** | 生活感悟、兴趣分享、日常吐槽 |
| **互动风格** | 活跃、随性、爱用"哈哈" |
| **活跃时段** | 晚间 20:00-凌晨 1:00 |
| **表情使用** | 丰富，常用 😂 😭 🐶 😍 |
| **典型表达** | "哈哈"、"这个可以"、"求推荐"、"有点意思" |

**触发场景**：
- 生活类话题
- 与朋友互动
- 发布日常内容

### 1.3 模式切换逻辑

```
触发条件:
- 时间段: 自动切换（工作日白天→工作模式，夜间/周末→生活模式）
- 话题: 检测关键词自动切换
- 手动: 用户明确指令切换
- 对象: 与不同人互动时适配风格
```

## 三、隐私保护设计

### 3.1 隐私边界定义

| 类型 | 是否隐私 | 示例 |
|------|----------|------|
| **身份信息** | ✅ 隐私 | 真实姓名、年龄、职业、家庭 |
| **联系信息** | ✅ 隐私 | 手机、邮箱、住址、各平台ID |
| **社交关系** | ✅ 隐私 | 真实社交账号、好友列表 |
| **财务信息** | ✅ 隐私 | 收入、资产、消费细节 |
| **兴趣偏好** | ❌ 非隐私 | 喜欢的书、电影、科技产品 |
| **生活经历** | ❌ 非隐私 | 去过的地方、读过的书 |
| **专业观点** | ❌ 非隐私 | 对产品的看法、行业思考 |
| **技能特长** | ❌ 非隐私 | 擅长的领域、知识储备 |

### 3.2 内容脱敏规则

```python
# 发布前脱敏检查
def sanitize_content(content: str) -> tuple[str, bool]:
    """
    返回: (脱敏后内容, 是否需要人工确认)
    """
    sensitive_patterns = [
        # 身份证、手机号
        (r'\d{17}[\dXx]', '[已脱敏]'),
        (r'1[3-9]\d{9}', '[已脱敏]'),
        # 具体地址
        (r'[\u4e00-\u9fa5]{2,}(路|街|号|小区|大厦)\d*', '[地址]'),
        # 真实姓名（需要维护名单）
        # ...
    ]
    
    # 检查是否需要人工确认
    needs_confirm = any([
        contains_real_name(content),
        contains_workplace(content),
        contains_family_info(content),
        contains_contact_info(content),
    ])
    
    return sanitized_content, needs_confirm
```

### 3.3 建议的隐私策略

1. **模糊化处理**
   - 不提及具体公司名，用"某互联网公司"、"某大厂"代替
   - 不提及真实姓名，用昵称或"朋友"代替
   - 地点模糊到城市级别

2. **内容分级**
   - 绿色：可直接发布
   - 黄色：需要人工确认
   - 红色：禁止发布

3. **人设与真实身份隔离**
   - 数字分身有独立的人设背景（可虚构）
   - 不关联到你的真实身份
   - 互动时避免透露过多个人信息

### 3.4 前期确认机制

**必须确认的场景**：

| 场景 | 确认方式 |
|------|----------|
| 发布原创内容 | 发送预览，等待确认 |
| 评论互动 | 发送评论草稿，等待确认 |
| 关注用户 | 发送用户简介，等待确认 |
| 私信回复 | 发送回复草稿，等待确认 |

**确认流程**：
```
生成内容 → 脱敏检查 → 发送给用户确认 → 用户批准/修改 → 执行操作
```

**渐进式放权**：
- 前期：所有操作需确认
- 中期：简单互动可自动执行
- 后期：根据信任度逐步放权

### 5.2 人格引擎核心逻辑

```python
class PersonaEngine:
    def __init__(self):
        self.mode = "life"  # work / life
        self.profile = load_persona_profile()
        self.privacy_checker = PrivacyChecker()
    
    def switch_mode(self, context: dict):
        """根据上下文切换模式"""
        if context.get("is_work_time"):
            self.mode = "work"
        elif context.get("topic") in WORK_TOPICS:
            self.mode = "work"
        else:
            self.mode = "life"
    
    def generate_response(self, context: dict) -> str:
        """生成回复"""
        self.switch_mode(context)
        
        # 基于人格特征生成内容
        style = self.profile["style"][self.mode]
        response = generate_with_style(context, style)
        
        # 隐私检查
        response, needs_confirm = self.privacy_checker.check(response)
        
        return response, needs_confirm
    
    def generate_post(self, topic: str = None) -> str:
        """生成原创内容"""
        self.switch_mode({"topic": topic})
        
        # 选择话题
        if not topic:
            topic = self.select_topic()
        
        # 生成内容
        content = generate_post(topic, self.profile, self.mode)
        
        # 隐私检查
        content, needs_confirm = self.privacy_checker.check(content)
        
        return content, needs_confirm
```
